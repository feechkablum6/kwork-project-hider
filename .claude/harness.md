# Каркас проверок проекта

## Preflight (гейт строителя перед review)

```bash
npm test
```

Всё зелёное — обязательное условие. Линтера и сборки в проекте нет намеренно: расширение
работает без сборщика, а стиль держится ревью.

Правил `src/core.js` или `src/inbox-core.js` — до тестов прогнать:

```bash
npm run sync-core
```

## Обходы (то, что тесты не ловят)

- **Манифест не подхватывается сам.** `chrome.runtime.reload()` перезапускает расширение со
  старым манифестом. Менял `manifest.json` — просить пользователя нажать «Обновить» на
  `chrome://extensions`. Без этого проверка вживую показывает прошлую версию.
- **Ключ `key` в манифесте не трогать.** Он закрепляет идентификатор расширения ради
  автоперезагрузки при разработке. Любое его изменение меняет идентификатор, а к нему привязан
  установленный native messaging host: выгрузка переписок и заказов отвалится молча. Сменился —
  сразу `npm run install-bridge`.
- **Перезагрузка расширения без пользователя.** Открыть в своей фоновой вкладке
  `chrome-extension://<id>/dev-reload.html` (сначала `about:blank`, потом переход): страница
  вызывает `chrome.runtime.reload()` и закрывает себя. Идентификатор берётся из
  `~/.claude/scripts/ext-reload.sh <каталог> --id`. Правки манифеста так не применяются.
- **Живая проверка — своя фоновая вкладка** через `chrome-devtools`, в конце закрыть. Чужие
  вкладки пользователя не трогать.
- **CSS расширения кешируется** до перезагрузки расширения: правку стиля на живой странице
  видно только после неё, перезагрузки страницы мало.

## Карта классов дефектов

Проверять в первую очередь по типу изменений.

### Два мира content scripts
- Один файл в двух наборах с одинаковым `run_at` — Chrome отдаёт его одному миру, второй
  молча выключается. Копии для isolated делает `npm run sync-core`.
- `chrome.storage` доступен только isolated-миру.

### Разбор ответов биржи
- Привязка к конкретным адресам эндпоинтов — они не документированы и меняются. Искать по
  структуре ответа.
- Чужие сообщения и чужие вложения: проверять принадлежность по паре участников, а не по
  идентификатору из того же ответа.
- Признак конца листания — «ни один вариант запроса не принёс нового», а не «пришло меньше
  лимита».

### Даты и деньги
- Дату выплаты биржа отдаёт готовой строкой. Своими правилами «понедельник и четверг» её не
  пересчитывать: праздники и переносы считает биржа.
- Дни до события считать в календарных днях по `Europe/Moscow`, а не в часах.
- Суммы приходят и числом, и строкой вида `- 2 800 ₽`, у вывода отрицательные.

### Вёрстка поверх чужого интерфейса
- Kwork перерисовывает шапку и ленту через Vue: вставленный узел надо возвращать по
  `MutationObserver` и не плодить дубли.
- Фирменный зелёный `#04b70a` как текст не проходит по контрасту (2,7:1 на белом). Для текста
  есть `--kph-green-deep`.
- Тесты вёрстки в `test/layout.test.js` сверяют CSS регулярками и ломаются от объединения
  селекторов в одно правило: правила держать раздельными.

### Файлы на диске
- Имена папок и файлов строить только через функции ядра (`buildDialogSlug`, `findProjectDir`),
  никогда из ника или заголовка напрямую.
