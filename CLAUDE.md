﻿# CLAUDE.md

## Стек

- Chrome Extension Manifest V3.
- JavaScript без сборщика и внешних зависимостей.
- Node.js `node --test`.

## Команды

- `npm test` — полный набор тестов.
- `npm run sync-core` — пересоздание копий ядра для изолированного мира после правок `src/core.js` или `src/inbox-core.js`.
- `npm run chat -- <ссылка>` — печать сохранённой переписки с клиентом.
- `npm version patch|minor` — новая версия сразу в `package.json` и `manifest.json`.
- `install.bat` (Windows) или `install.command` (macOS) — установка моста, который пишет переписки и заказы на диск.
- `powershell -ExecutionPolicy Bypass -File .\scripts\generate-icons.ps1` — пересоздание иконок.

## Структура

- `src/core.js` — чистая тестируемая логика ленты, доступная в браузере и Node.js.
- `src/inbox-core.js` — чистая логика переписок: распознавание сообщений, склейка, рендер markdown.
- `src/project-core.js` — чистая логика заказов: разбор состояния страницы заказа, имя папки, рендер markdown.
- `src/project-content.js` — чтение страницы заказа в изолированном мире по кнопке «Извлечь».
- `src/payout-core.js` — чистая логика выплаты: отбор незакрытых заявок на вывод, сумма, разбор даты биржи, срок словами.
- `src/payout-source.js` — получение операций баланса с любой страницы Kwork, листание и кеш в `chrome.storage`.
- `src/payout-content.js` — виджет ближайшей выплаты в шапке рядом с балансом.
- `src/report-toggle.js` — кнопка «Скрыть/Открыть» у блока «Промежуточный отчет» на странице заказа; состояние одно на все заказы (`reportCollapsed` в `chrome.storage`).
- `src/core-isolated.js`, `src/inbox-core-isolated.js` — сгенерированные копии ядер для изолированного мира, вручную не править.
- `src/feed-main.js` — перехват запросов Kwork в MAIN world и объединение страниц.
- `src/inbox-main.js` — перехват ответов переписки и догрузка истории в MAIN world.
- `src/inbox-crawler.js` — массовая выгрузка всех переписок в MAIN world: список диалогов, подбор листания, полная история.
- `src/ticks-main.js` (MAIN world) и `src/ticks-content.js` — третья оранжевая галочка «есть у Claude» у сообщений, сохранённых на диск; ключ «автор:время» (`messageKey`), список от моста `message-keys`.
- `src/popup.html`, `src/popup.css`, `src/popup.js`, `src/popup-view.js` — попап с кнопкой выгрузки и прогрессом; тексты состояний считает `popup-view.js`.
- `src/reply-core.js` (чистая логика), `src/reply-main.js` (MAIN world), `src/reply-content.js` — панель «Черновик агента» над полем на `/inbox` и `/track`: части из `data/drafts/<ник>.json`, кнопка заполняет «Ответить»/«Цитировать», текст, форму предложения и опций; отправляет только пользователь. Текст по кнопке набирается по знаку (~1300 знаков/мин, `typingSteps`), чтобы клиент видел «печатает»: сигнал шлёт сам Kwork (`pullIsTypeMessage`); повторное нажатие, «Отправить» и скрытая вкладка дописывают сразу, правка поля останавливает. Новый черновик сам заменяет в поле текст, вставленный панелью из прошлого (правку пользователя не трогает); отправленное панель видит на странице, не дожидаясь диска. Расширение перезагрузилось (страница потеряла с ним связь, `chrome.runtime.id` пуст) — вкладка с пустыми полями обновляется сама, и скрытая тоже, не чаще раза в минуту (`orphanAction`, отметка в `sessionStorage`); набран текст, заполнена опция или цена, прикреплён файл или выбрана цитата — плашка «Расширение обновилось» с кнопкой «Обновить страницу», опустели поля на двух проверках подряд — обновление.
- `src/live-main.js` (MAIN world) — догон новых сообщений без живого канала Kwork (молчит с 24.10.2026): пока вкладка `/inbox…` или `/track` видна — сразу и раз в 20 с — шлёт сайту его же `pushsteam-connection-restore` (переписка, список диалогов, счётчики); сообщение заказа, которого нет в открытой переписке, дорисовывает `onNewOrderTrack` по последнему элементу списка диалогов; на странице заказа `api/track/getnewtracks` и при новом треке — `refresh_track.pull`. Пока канал присылает события (последнее — меньше 2 минут назад), опрос молчит.
- `src/keepalive-content.js`, `src/restart.html`, `src/restart.js` — автоперезапуск: каждая страница Kwork сразу и раз в минуту подгружает скрытую рамку `restart.html` (web_accessible_resources только для kwork.ru; без `use_dynamic_url`: с ним Chrome не пускает рамку по адресу из `getURL`, проверено 26.10.2026; адрес берётся один раз — осиротевший после перезапуска скрипт продолжает подгружать рамку). Рамка шлёт фоновому скрипту `kph-ping`: «Receiving end does not exist» дольше 50 с подряд (полоса промахов `autoRestartMissSince` в `chrome.storage`, общая для страниц и вкладок) — `chrome.runtime.reload()`, не чаще раза в 10 минут (`autoRestartAt`). Без открытой страницы Kwork не работает; открытые страницы после перезапуска нужно обновить.
- `src/content.js` — скрытие карточек и работа с `chrome.storage`.
- `src/feed-content.js` — DOM-адаптер автоподгрузки в isolated world.
- `src/inbox-content.js` — сбор переписки в isolated world, скачивание вложений и передача в фоновый скрипт.
- `src/background.js` — service worker, единственная точка связи с native messaging хостом; раз в минуту сам дописывает новые сообщения, вложения и отклики (`kwork.ru/offers`) без открытой вкладки Kwork; раз в 3 минуты — события живых заказов (`/get_manage_orders` → треки, мост `save-order-events`), раз в 10 минут — статус неоплаченных предложений (мост `open-offers`).
- `native_host/` — мост на Node.js: протокол native messaging и запись файлов переписок.
- `native_host/sync-wake.js` — заявки хука «выгрузи сейчас» (`data/sync-requests` → push расширению → `data/sync-done/<id>.json`); слушает только мост постоянного порта (`subscribe`).
- `native_host/waker.js`, `wake-core.js`, `claude-runner.js` — будильщик агентов: последним писал клиент и это не разобрано (`data/wake-state.json`, отметки `data/wake-dirty`) → побудка в чат заказа Claude Desktop (один на заказ: наш прошлый, иначе свежайший чат Desktop папки заказа; клиент без заказа — свой чат в корне Kwork), номер — в `state.chats` по ключу маршрута. Чат открыт — сообщение в его сокет (`~/.claude/sessions`, нужен `crossSessionInbound: accept`); спит или в архиве — через чат-диспетчер (`dispatcher/CLAUDE.md`, номер в `data/dispatcher.json`): мост пишет ему в сокет строку со ссылкой на файл с текстом побудки (`data/wake-texts/<id>.md`; текст клиента до диспетчера не доходит), он шлёт её `send_message` Desktop (поднимает чат сверх лимита, окно не трогает); спящий диспетчер — ссылка `claude://resume` только в первые 2 минуты работы Desktop или когда пользователь отошёл (`HIDIdleTime` ≥ 60 с; закрытый Desktop она тогда запускает), не чаще раза в 5 минут; ссылка не помогла (Desktop держит предел живых чатов) или пользователь за компьютером — свободный открытый чат Kwork с самой старой записью (не из заказов этого клиента) получает «[Kwork-служебное]» с просьбой послать диспетчеру команду расписания (сообщение от чата Desktop поднимает его и сверх предела; не чаще раза в 5 минут и не больше двух раз в час; сам служебный обмен работой в чате не считается, правило агента — раздел «Служебное: поднять диспетчер» в `побудка.md`); номер запроса — `<побудка>.<попытка>`; новый процесс диспетчера сначала получает «расписание» (живое расписание не даёт Desktop его усыпить). Дошло — по записи `user` или вложению `queued_command` (занятый чат) с меткой `[Kwork-побудка #id]` в журнале чата (сокет — 20 с, диспетчер — 90 с, от последнего «занят» чата или диспетчера — работает или ждёт ответа пользователя; сон мака не в счёт), нет — повтор через диспетчера; метки разобранного сдвигаются только по метке. Чата в Desktop нет (новый чат Desktop диспетчеру создавать не даёт) — `claude -p` в новом чате (`--name`: имя заказа, без заказа — ник; лог `data/wake-runs/<id>.log`), после конца чат один раз добавляется в список Desktop, когда Desktop не на переднем плане. Чат держит терминал — пропуск. Сбои — только в `bridge.log`. Бинарь, модель и уровень — `KPH_CLAUDE_BIN`/`KPH_CLAUDE_MODEL`/`KPH_CLAUDE_EFFORT`. Правила агента — `~/Projects/Kwork/docs/побудка.md`.
- `native_host/reroute.js`, `scripts/kwork-reroute.mjs` — пересылка побудки в другой заказ клиента: у клиента несколько заказов, побудка ушла туда, где работали последним, а сообщение про другой — агент оставляет заявку с номером побудки (`data/reroute-requests`; команда — в тексте побудки), будильщик возвращает отметки разобранного (сообщения и события) на те, что были до неё (`state.delivered`, последние доставки за сутки), и будит чат названного заказа теми же сообщениями (`state.reroute` до подтверждения); одна пересылка на побудку, пересланную дальше не пересылают.
- `native_host/snooze.js`, `scripts/kwork-snooze.mjs` — отметка «ждём клиента»: агент оставляет заявку (`data/snooze-requests`), будильщик переносит её в `state.snoozed`; побудка по маршруту снимает отметку.
- `native_host/t3-client.js`, `t3-live.js` — прежний транспорт T3: мост их не вызывает; удалить после живой проверки Claude Code.
- `scripts/install-bridge.mjs`, `scripts/kwork-chat.mjs` — установка моста и чтение переписок из терминала.
- `scripts/kwork-shared.mjs` — общее для сводки и сверки: папка переписок, связь заказ ↔ ник, рабочие копии T3, формат времени.
- `scripts/kwork-brief.mjs` — сводка переписки для агента Claude Code (хуки SessionStart/UserPromptSubmit через `~/.claude/scripts/kwork-chat-brief.sh`): новые сообщения клиента, кто ответил последним, пути к файлам; на каждом ходе — не отправлен ли черновик агента этого чата или заказа. Связь заказа с клиентом — `~/Projects/Kwork/docs/заказы-клиенты.md`.
- `scripts/kwork-drafts.mjs` — сверка черновиков агента с отправленным: `capture` (Stop-хук `~/.claude/scripts/kwork-draft-capture.sh`) и `sync`; итог дописывает в `~/.claude/skills/estimate/data/sent.md`.
- `scripts/sync-version.mjs` — после `npm version …` переносит номер версии в `manifest.json`. Установщик знает Windows и macOS: реестр и `exe` против манифестов в папках браузеров и `sh`.
- `test/` — тесты ядра, перехватчика, моста, manifest и интеграционных контрактов DOM.

## Правила

- Сохранять двухслойную схему MAIN world / isolated world; `chrome.storage` доступен только isolated content script.
- Тестируемые вычисления и разбор DOM-состояния выносить в `src/core.js`, логику переписок — в `src/inbox-core.js`.
- Переписки и заказы писать на диск только через мост: расширение не хранит их в `chrome.storage` и никуда не отправляет.
- Раскладка папки заказов — папка на заказ: `<номер>-<заголовок>/заказ.md`, `данные.json`, `файлы/`. Папка заказов лежит рядом с папкой переписок, путь берётся из `projectsDir` настройки моста.
- Раскладка папки переписок — папка на диалог: `<ник>/переписка.md`, `<ник>/данные.json`, `<ник>/файлы/`. Имена держать в константах ядра, не дублировать строками.
- Пользовательские статусы и ошибки писать кратко на русском языке.
- Не добавлять сборщик или зависимости без реальной необходимости.
