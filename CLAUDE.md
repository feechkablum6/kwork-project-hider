# CLAUDE.md

## Стек

- Chrome Extension Manifest V3.
- JavaScript без сборщика и внешних зависимостей.
- Node.js `node --test`.

## Команды

- `npm test` — полный набор тестов.
- `npm run sync-core` — пересоздание копий ядра для изолированного мира после правок `src/core.js` или `src/inbox-core.js`.
- `npm run chat -- <ссылка>` — печать сохранённой переписки с клиентом.
- `install.bat` — установка моста, который пишет переписки на диск.
- `powershell -ExecutionPolicy Bypass -File .\scripts\generate-icons.ps1` — пересоздание иконок.

## Структура

- `src/core.js` — чистая тестируемая логика ленты, доступная в браузере и Node.js.
- `src/inbox-core.js` — чистая логика переписок: распознавание сообщений, склейка, рендер markdown.
- `src/project-core.js` — чистая логика заказов: разбор состояния страницы заказа, имя папки, рендер markdown.
- `src/project-content.js` — чтение страницы заказа в изолированном мире по кнопке «Извлечь».
- `src/core-isolated.js`, `src/inbox-core-isolated.js` — сгенерированные копии ядер для изолированного мира, вручную не править.
- `src/feed-main.js` — перехват запросов Kwork в MAIN world и объединение страниц.
- `src/inbox-main.js` — перехват ответов переписки и догрузка истории в MAIN world.
- `src/inbox-crawler.js` — массовая выгрузка всех переписок в MAIN world: список диалогов, подбор листания, полная история.
- `src/popup.html`, `src/popup.css`, `src/popup.js`, `src/popup-view.js` — попап с кнопкой выгрузки и прогрессом; тексты состояний считает `popup-view.js`.
- `src/content.js` — скрытие карточек и работа с `chrome.storage`.
- `src/feed-content.js` — DOM-адаптер автоподгрузки в isolated world.
- `src/inbox-content.js` — сбор переписки в isolated world, скачивание вложений и передача в фоновый скрипт.
- `src/background.js` — service worker, единственная точка связи с native messaging хостом.
- `native_host/` — мост на Node.js: протокол native messaging и запись файлов переписок.
- `scripts/install-bridge.mjs`, `scripts/kwork-chat.mjs` — установка моста и чтение переписок из терминала.
- `test/` — тесты ядра, перехватчика, моста, manifest и интеграционных контрактов DOM.

## Правила

- Сохранять двухслойную схему MAIN world / isolated world; `chrome.storage` доступен только isolated content script.
- Тестируемые вычисления и разбор DOM-состояния выносить в `src/core.js`, логику переписок — в `src/inbox-core.js`.
- Переписки и заказы писать на диск только через мост: расширение не хранит их в `chrome.storage` и никуда не отправляет.
- Раскладка папки заказов — папка на заказ: `<номер>-<заголовок>/заказ.md`, `данные.json`, `файлы/`. Папка заказов лежит рядом с папкой переписок, путь берётся из `projectsDir` настройки моста.
- Раскладка папки переписок — папка на диалог: `<ник>/переписка.md`, `<ник>/данные.json`, `<ник>/файлы/`. Имена держать в константах ядра, не дублировать строками.
- Пользовательские статусы и ошибки писать кратко на русском языке.
- Не добавлять сборщик или зависимости без реальной необходимости.

## Анти-паттерны

- DO NOT запускать фоновую сборку штатным кликом по пагинации: он включает прелоадер Kwork на всё время запросов. Сборка стартует отдельным событием MAIN world, а клик допустим только после готовности данных для итоговой отрисовки.
- DO NOT запускать полную фоновую сборку на каждый промежуточный фильтр или страницу: ждать одну секунду без новых действий, отменять устаревшие XHR и оставлять штатную пагинацию для выдачи больше десяти страниц.
- DO NOT добавлять действия в `.wants-card__right`: абсолютная колонка бюджета перекрывает «Показать полностью» при увеличении высоты; использовать `.want-card__buttons`.
- DO NOT решать право на объединение только сравнением подписи полей запроса: Kwork шлёт свой набор полей, и запрос от собственного клика расширения остаётся неузнанным, а лента перерисовывается дважды. Клик итоговой отрисовки объявляется событием `kph-feed-render`, а собранная лента сверяется с проектами, уже показанными в DOM.
- DO NOT подключать один и тот же файл к двум наборам content scripts с одинаковым `run_at`: Chrome отдаёт его только одному набору, второй мир остаётся без ядра и молча выключается. Изолированный мир использует `src/core-isolated.js` — копию, которую создаёт `npm run sync-core`.
- DO NOT откладывать стартовую сборку до готовности DOM и секундной паузы: у пользователя со скрытой первой страницей экран остаётся пустым всё это время. Сборка стартует при установке перехватчика, пауза остаётся только для запросов Kwork при смене фильтра.
- DO NOT привязывать разбор переписки к конкретным адресам запросов Kwork: внутренние эндпоинты биржи не документированы и меняются. Сообщения ищутся по структуре ответа (`collectMessages`), а шаблон запроса для догрузки истории берётся из перехваченного запроса.
- DO NOT искать распакованное расширение в `Preferences`: Chrome держит `extensions.settings` в `Secure Preferences`, и установщик моста без него не находит идентификатор.
- DO NOT строить имя файла переписки из ника клиента напрямую: ник приходит с биржи и уводит запись за пределы папки. Имя даёт `buildDialogSlug`.
- DO NOT доверять ответу /inbox_more_messages как переписке с одним клиентом: с allUnread=true и большим лимитом биржа отдаёт сводную ленту по всем диалогам, и в файл попадают чужие сообщения. Каждое сообщение проверяется filterDialogMessages по паре участников (mfrom/mto, MSGFROM/MSGTO).
- DO NOT считать историю прочитанной по числу сообщений в ответе: Kwork отдаёт пачку с повторами, после дедупа их меньше лимита, и проверка `< limit` останавливает листание на первом же запросе. Признак конца — ни один вариант запроса не принёс новых сообщений.
- DO NOT считать историю переписки полной по одному ответу `/inbox_more_messages`: он отдаёт последние 50 сообщений, а параметр глубины Kwork не публикует. Рабочий вариант подбирается `buildHistoryProbes` на живом запросе и переиспользуется до конца диалога.
- DO NOT просить пользователя самому проверить вход и открытый Kwork: расширение определяет это само по тому, куда биржа увела вкладку переписок, и предлагает единственное действие — открыть Kwork.
- DO NOT искать диалоги только по ссылкам `a[href*="/inbox/"]`: новый интерфейс отдаёт `/new_inbox/…`, а список подгружается прокруткой. Список ждут, прокручивают до конца и дополняют известными идентификаторами.
- DO NOT открывать диалог ради идентификатора клиента: страница `/user/<ник>` отдаёт его полем `userProfileId` одним запросом, и такие запросы идут параллельно. Навигация по вкладке остаётся запасным путём для тех, кого профиль не отдал.
- DO NOT качать вложения переписки из фонового скрипта: без адреса и кук страницы Kwork отдаёт страницу ошибки вместо файла. Файлы забирает вкладка Kwork, а фоновый скрипт только пересылает куски мосту.
- DO NOT давать вложениям имя прямо из поля файла: скриншоты приходят как `image.png`, голосовые — числом, и файлы затирают друг друга. Имя строит `resolveAttachmentFiles` из даты и времени сообщения, поэтому оно не зависит от того, какие сообщения пришли в этой порции.
- DO NOT подтверждать принадлежность сообщения диалогу идентификатором собеседника из того же ответа: страница переписки видит и запросы соседних диалогов, и чужие вложения уезжают в чужую папку. Когда у сообщения есть имена участников, решают только они.
- DO NOT запускать мост командным файлом: Chrome 151 принимает native messaging host только настоящей программой, а `.bat` отклоняет с ошибкой «мост не найден», из-за чего перестаёт работать и выгрузка переписок. Установщик собирает `kwork-bridge.exe` через `csc.exe` и регистрирует хост под именем `ru.kwork.hider.host`; старое имя `ru.kwork.hider.bridge` Chrome продолжает отвергать даже после исправления пути, поэтому оно удаляется из реестра.
- DO NOT собирать данные заказа из вёрстки карточки: описание в ленте обрезано, допустимый бюджет и прикреплённые файлы там не показаны. Страница заказа отдаёт всё одним объектом состояния (`wantData`), его и разбирает `extractWantData`.
- DO NOT качать файлы заказа из вкладки Kwork: ссылка переадресуется на `cdn-edge.kwork.ru`, а тот не разрешает межсайтовые запросы, и запрос со страницы обрывается. Файлы заказа качает фоновый скрипт по `host_permissions`; для вложений переписки правило обратное — их отдаёт сама биржа, и качает их вкладка.
- DO NOT искать папку заказа, собирая её имя заново: имя содержит заголовок, а при записи файлов известен только номер. Папка ищется по номеру (`findProjectDir`) и переименовывается, если заказчик сменил заголовок.
- DO NOT отсеивать служебные диалоги биржи только в обходчике: ключи приходят ещё из состояния страницы и запомненных идентификаторов, и переписка с поддержкой оказывается на диске. Признак даёт `isServiceDialogKey` в ядре, проверка стоит на итоговом списке обхода и в мосте при записи.
